# 🛡️ API 安全加固说明

本文说明 BEpusdt 在商户对接链路上的几项安全防护，部分思路参考自 [GMWalletApp/epusdt](https://github.com/GMWalletApp/epusdt)。

## 1. 回调地址防 SSRF（默认开启）

商户下单时提交的 `notify_url` 会由 BEpusdt 服务器主动请求。如果不加限制，拿到对接令牌的人可以把回调地址填成
`http://127.0.0.1:xxxx/...`、`http://192.168.x.x/...`、`http://169.254.169.254/...`（云服务器元数据）等，
借网关之手访问内网服务（SSRF）。

现在的防护分两层：

| 阶段 | 行为 |
|------|------|
| 下单时 | `notify_url` 是 `localhost`、内网 IP、保留地址，或域名解析到这些地址时，直接拒绝下单并返回明确错误 |
| 回调时 | 每次建立连接（包括 302 跳转后的新连接）都会校验 **DNS 解析后的真实 IP**，防止 DNS 重绑定等绕过 |

被拦截的地址包括：回环（127.0.0.0/8、::1）、私有网段（10/8、172.16/12、192.168/16、fc00::/7）、
链路本地（169.254/16、fe80::/10，含云元数据）、CGNAT（100.64/10）、组播、保留地址，以及 IPv4 映射 / NAT64 写法。

> 下单时如果商户域名临时解析失败不会拒单，最终以回调时的拨号校验为准。

### 商户系统和 BEpusdt 在同一台服务器 / 内网？

例如 V2Board / Xboard 和 BEpusdt 装在同一台机器，回调地址写的是 `http://127.0.0.1/...`，需要到
**后台 → 系统设置 → API设置**，打开 **「回调允许内网地址」**（配置项 `api_callback_allow_private=1`）。

打开后行为与旧版本完全一致（允许内网，并遵循 `HTTP_PROXY` 等环境变量代理）。

> 防护开启时回调会直连商户，不经过 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量代理，因为经过代理就无法校验真实目标地址。

### 升级注意

升级前已经创建、回调地址指向内网的待回调订单，升级后回调会失败并进入重试；按上面打开开关后，在后台订单详情手动重发回调即可。

后台「手动创建订单」原先会回调网关自身的空接口，现在直接标记回调成功，不再发起 HTTP 请求。

## 2. API 来源 IP 白名单（可选）

**后台 → 系统设置 → API设置 → API 来源IP白名单**（配置项 `api_ip_whitelist`）。

- 支持单个 IP 或 CIDR 网段，逗号 / 分号 / 换行分隔，例如 `203.0.113.10, 198.51.100.0/24`
- 留空表示不限制（默认）
- 修改后立即生效，无需重启
- 只作用于服务端下单 / 取消接口 `/api/v1/order/*`；易支付 `submit.php` 是买家浏览器跳转发起的，来源是买家 IP，因此不受白名单限制

### 真实 IP 是怎么识别的

- 直连对端是公网地址时：直接使用 TCP 对端 IP，**忽略** `X-Forwarded-For`，防止伪造请求头绕过白名单
- 直连对端是本机 / 内网地址（即经过 Nginx、Caddy、1Panel、宝塔等反向代理）时：从 `X-Forwarded-For` 右侧取第一个非内网地址，其次 `X-Real-IP`

请确认反向代理有正确传递 `X-Forwarded-For`（Nginx：`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`）。

> 如果站点套了 Cloudflare 且没有在 Nginx 配置 `real_ip`，识别到的会是 Cloudflare 节点 IP，白名单需要另行处理。

## 3. 签名常量时间比较

Epusdt 接口与易支付接口的签名校验改为常量时间比较，避免通过响应耗时差异逐字节猜测签名。对接方式与签名算法均不变。
